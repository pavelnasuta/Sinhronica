# Достижения спортсмена — дизайн

## Цель

Добавить в Sinhronica самостоятельную вкладку «Достижения», где ребёнок фиксирует результаты соревнований и нормативов, видит хронологию собственных показателей и их динамику по дисциплинам. Все данные остаются только в `localStorage` текущего браузера.

## Навигация и состояния

- В нижней навигации появляется четвёртая вкладка «Достижения» с иконкой кубка (`Trophy`). Порядок: «Главная», «Идеи», «Галерея», «Достижения».
- На ширине 320 px четыре равные ячейки остаются читаемыми; подписи не должны обрезаться или создавать горизонтальный скролл.
- Пустое состояние использует существующую иллюстрацию `public/onboarding/progress.webp`: Акви держит золотую звезду. Текст: «Здесь будут твои победы» и короткое объяснение, что можно сохранить результат соревнований или норматива. Основное действие: «Добавить достижение».
- При наличии записей вверху раздела остаётся компактная шапка: маленькая Акви, заголовок «Твои достижения» и поддерживающий текст. Иллюстрация выводится в фиксированном контейнере с `object-fit: contain`, без обрезания.
- Весь экран доступен с клавиатуры, у кнопок есть понятные подписи, а редактирование и удаление открываются в доступных диалогах.

## Модель данных

Каждая запись — локальный `Achievement`:

```ts
type AchievementDiscipline =
  | 'figures'
  | 'combo'
  | 'team'
  | 'acrobatics'
  | 'duet'
  | 'solo'
  | 'mixed-duet'
  | 'custom'

type AchievementMedal = 'gold' | 'silver' | 'bronze' | 'participation' | 'none'

type Achievement = {
  id: string
  performedOn: string // ISO local date YYYY-MM-DD
  eventName: string
  discipline: AchievementDiscipline
  customDiscipline?: string
  score: number
  medal: AchievementMedal
  createdAt: string
  updatedAt: string
}
```

- `performedOn`, `eventName`, `discipline` и `score` обязательны. Название события обрезается по краям и хранится в нормализованном виде без лишних пробелов.
- Балл — неотрицательное конечное число, допускающее дробную часть до двух знаков.
- Для `custom` обязательно `customDiscipline`; иначе оно не сохраняется.
- Названия встроенных дисциплин: «Нормативы фигур», «Комби», «Группа», «Акробатика», «Дуэт», «Соло», «Микст-дуэт», «Своя дисциплина».
- Медали: «1 место», «2 место», «3 место», «Участие», «Без медали». Медали — достиженческие, поэтому для них используется золотая палитра дизайн-системы; спортивные разряды остаются без золота.
- Хранилище: `sinhronica:achievements:v1`. Некорректный, частично испорченный или семантически неверный сохранённый объект не попадает в интерфейс. При недоступном `localStorage` данные остаются в памяти с тем же ясным предупреждением, что используется в текущих локальных разделах.

## Создание, редактирование и удаление

- Кнопка «Добавить достижение» открывает форму в диалоге.
- Поля формы в порядке: дата проведения, соревнование/событие, дисциплина, поле своей дисциплины при выборе соответствующего варианта, балл, медаль.
- Поле даты не разрешает будущие даты; максимальная дата строится по локальному календарю.
- Новая запись создаётся с UUID и временными метками; при редактировании сохраняются `id` и `createdAt`, меняется только `updatedAt`.
- Карточка открывает форму редактирования. У каждой карточки есть отдельное действие удаления.
- Удаление требует подтверждения и удаляет только выбранную локальную запись. После удаления фокус и список остаются в предсказуемом состоянии.

## Хронология, динамика и фильтрация

- Карточки сортируются по дате проведения от новых к старым; при равной дате — по `createdAt` от новых к старым. Дата добавления никогда не влияет на основную хронологию.
- Карточка показывает дату, соревнование, дисциплину, балл и медаль. Подписи и пиктограммы не являются единственным носителем смысла.
- Динамика считается только внутри одинаковой нормализованной дисциплины. Для встроенной дисциплины ключ — её ID; для своей — ID `custom` плюс нормализованное название.
- Для записи находится результат той же дисциплины с ближайшей более ранней датой проведения. Результаты на ту же дату не участвуют в сравнении.
- Если текущий балл больше предыдущего, карточка показывает зелёную стрелку вверх и разницу. Если меньше — красную стрелку вниз и разницу. При равных баллах — нейтральная подпись «Без изменений». У первого результата дисциплины динамика не показывается.
- У раздела есть поиск по событию и фильтр по дисциплине. Пустой результат фильтра объясняет, что подходящих достижений нет.
- Сверху при наличии записей выводятся три компактные сводки: число результатов, число медалей (все варианты кроме «Без медали») и лучший балл по текущему фильтру. Сводки получают данные только из локального списка.

## Экспорт и удаление данных

- Общий экспорт настроек становится форматом версии 2 и содержит `achievements` наряду с профилем, идеями и темой.
- Экспорт по-прежнему создаётся только вручную пользователем и никуда не отправляется.
- Действие «Удалить данные с устройства» в настройках также очищает `sinhronica:achievements:v1`, не затрагивая чужие ключи `localStorage`.

## Вне рамок первого релиза

- Серверная синхронизация, аккаунты, фотографии/сканы дипломов, публикация достижений, рейтинги, уведомления, импорт JSON и графики не добавляются.
- Дополнительные поля (тренер, место проведения, заметки) не добавляются: карточка должна быть короткой и понятной ребёнку.

## Проверка

- Unit-тесты: валидация и гидратация сохранённых записей, создание/редактирование/удаление, сортировка, ближайший предыдущий результат, рост/падение/равенство, очистка только namespaced-ключей и экспорт v2.
- UI-тесты: пустое состояние с Акви, форма, условное поле своей дисциплины, диалог удаления, динамика и фильтрация.
- E2E: добавить задним числом результаты в разном порядке, убедиться в сортировке и сравнении по дате проведения; проверить редактирование и удаление.
- Визуальная проверка: 320×568 и 390×844, пустое и заполненное состояния, отсутствие горизонтального overflow и отсутствие обрезания Акви.
- До публикации: полный набор unit/E2E тестов, typecheck, lint, production build с `VITE_BASE_PATH=Sinhronica`, проверка Workbox precache и опубликованной страницы.
