# Карточки номеров — дизайн

## Цель

Заменить пустой раздел «Номера» локальным планировщиком, в котором спортсменка хранит понятное описание номера и его структуру. Это тренировочный инструмент, а не официальная карточка тренера и не калькулятор заявленной сложности.

## Граница продукта

- Пользователь создаёт, открывает, редактирует и удаляет карточки номеров в разделе «Номера».
- Все записи остаются только в `localStorage` текущего браузера и включаются в ручной экспорт данных.
- Интерфейс нигде не рассчитывает DD, не проверяет официальный состав элементов и не называет запись заявкой или карточкой тренера.
- Фигуры и расчёт за фигуры не используются в модели номера.

## Навигация и состояния

- Нижняя навигация не меняется: «Номера» остаётся третьей вкладкой.
- Пустое состояние использует существующую Акви из `onboarding/practice.webp`, заголовок «Твои номера» и действие «Создать номер».
- При наличии записей экран показывает компактный список карточек, отсортированный по `updatedAt` от новых к старым; основное действие «Новый номер» остаётся доступным.
- Открытая карточка имеет отдельный экран с кнопкой возврата к списку, а не модальное окно: длинную схему удобно читать на телефоне.

## Модель данных

```ts
type RoutineDiscipline = 'solo' | 'duet' | 'mixed-duet' | 'group' | 'combo' | 'acro-group' | 'custom'
type RoutineProgramType = 'technical' | 'free' | 'not-specified'
type RoutineContext = 'training' | 'competition' | 'show'
type RoutineBlockType = 'element' | 'formation' | 'transition' | 'note'

type RoutineBlock = {
  id: string
  type: RoutineBlockType
  title: string
  startSecond?: number
  endSecond?: number
  manualDifficulty?: number
  note?: string
}

type Routine = {
  id: string
  title: string
  context: RoutineContext
  eventName?: string
  discipline: RoutineDiscipline
  customDiscipline?: string
  programType: RoutineProgramType
  ageGroup: string
  activeAthleteCount: number
  reserveAthleteCount: number
  athleteNames: string[]
  targetDurationSeconds?: number
  generalNote?: string
  blocks: RoutineBlock[]
  createdAt: string
  updatedAt: string
}
```

- Обязательны: название, контекст, дисциплина, возрастная группа и число действующих участниц.
- Своя дисциплина обязательна только для `custom`; иначе поле не сохраняется.
- Числа участниц, резервов и секунд — целые неотрицательные; длительность и время блока необязательны.
- Ручная сложность блока — необязательное неотрицательное число. Она доступна только у блока «Элемент»; её сумма отображается как «Черновая сложность» без статуса официальной заявленной сложности.
- У блока обязательны тип и короткий заголовок. `startSecond` и `endSecond` задаются в секундах от начала номера; если заданы оба, конец не раньше начала.
- Имена участниц необязательны и не обязаны совпадать с количеством: это личная карточка планирования, не заявка на соревнования.
- Новая запись получает UUID и временные метки. Любая правка обновляет только `updatedAt`.

## Экран номера

### Список

- Карточка списка показывает название, дисциплину, тип программы, возраст, число участниц и количество блоков.
- Поиск, фильтры, копирование и публикация не добавляются в первом релизе.

### Создание и редактирование

- Форма открывается в доступном диалоге.
- Поля идут в порядке: название; контекст и событие; дисциплина/свой вариант; тип программы; возраст; основной и резервный состав; имена через запятую; целевая длительность; общая заметка.
- Редактирование и удаление доступны из открытой карточки. Удаление требует подтверждения.

### Структура

- На открытой карточке отображается таймлайн блоков в ручном порядке.
- Блоки: «Элемент», «Построение», «Переход», «Заметка». Каждый показывает название, при наличии — диапазон времени, ручную сложность элемента и пояснение.
- Спортсменка добавляет и редактирует блоки в диалоге, меняет порядок кнопками «Выше» и «Ниже» и удаляет с подтверждением.
- Если у блока есть время, экран показывает его как `м:с`; блок без времени остаётся допустимым. Ручные сложности элементов суммируются в «Черновую сложность».
- Таймлайн не определяет сложность автоматически, не классифицирует технику и не создаёт автоматических предупреждений по спортивным правилам.

## Локальные данные

- Новый ключ: `sinhronica:routines:v1`.
- Повреждённые, частичные или семантически неверные записи не выводятся; статус недоступного/восстановленного хранилища следует существующему паттерну достижений и прогресса фигур.
- Общий экспорт становится версией 4 и добавляет `routines`.
- «Удалить данные с устройства» удаляет только этот ключ вместе с существующими ключами Sinhronica; чужие данные браузера не затрагиваются.

## Вне рамок первого релиза

- Расчёт заявленной сложности, официальная совместимость с карточкой тренера, нормы наполнения, квоты, штрафы и проверка программы.
- Загрузка/хранение аудиофайлов, видео, фото, внешние ссылки на музыку, совместное редактирование, аккаунты и облачная синхронизация.
- Автоматическое построение хореографии, оценка техники, публикация и отправка номера.

## Проверка

- Unit-тесты: нормализация карточки и блоков, гидратация, CRUD, порядок блоков, сохранение и очистка локального хранилища, экспорт версии 4.
- UI-тесты: пустое состояние, создание карточки, изменение, открытие структуры, добавление/перестановка/удаление блока.
- E2E: создать номер на узком телефоне, добавить блоки, убедиться в сохранении после перезагрузки и отсутствии горизонтального overflow.
- До публикации: полный набор unit/E2E тестов, typecheck, lint, production build с `VITE_BASE_PATH=Sinhronica`, проверка опубликованной страницы.
